Section I: Bezier Curves and Surfaces

Part 1: Bezier curves with 1D de Casteljau subdivision

De Casteljau's algorithm evaluates a Bézier curve at a parameter \(t \in [0,1]\) by repeated linear interpolation on the points selected. Given \(n\) control points \(p_0, \dots, p_{n-1}\), one step produces \(n-1\) new points: \[ p_i' = (1-t)\,p_i + t\,p_{i+1}. \] We repeat this algorithm until there is only one point, which is guaranteed to lie on the curve. Then, by sliding our parameter \(t\), we can generate the entire curve. The code written for this section was the evaluateStep method which does one step of the De Casteljau algorithm. 

std::vector<Vector2D> BezierCurve::evaluateStep(std::vector<Vector2D> const &points)
{
  std::vector<Vector2D> newPoints;
  for (int i = 0; i < points.size() - 1; i++)
  {
    Vector2D newPoint = (1 - t) * points[i] + t * points[i + 1];
    newPoints.push_back(newPoint);
  }
  return newPoints;
}

Part 2: Bezier surfaces with separable 1D de Casteljau

We extend De Casteljau's algorithm to create Bézier surface (patch), an \(n \times n\) grid of 3D control points and two parameters \((u, v)\). We accomplish this as follows. First, treat each row of the grid as its own 1D Bézier curve and evaluate it at \(u\). That leaves one point per row, \(n\) points in total. Those \(n\) points are the control points of a new 1D curve running in the other direction. Evaluating that curve at \(v\) gives the final point on the surface. As before, we then adjust \((u, v)\) to get the surface.

In terms of code, the evaluateStep function was utilized to create 1D-evaluation methods that were used to generate the surface. 

Vector3D BezierPatch::evaluate1D(std::vector<Vector3D> const &points, double t) const
{
  vector<Vector3D> pointsCopy = points;
  while (pointsCopy.size() > 1)
  {
    pointsCopy = evaluateStep(pointsCopy, t);
  }
  return pointsCopy[0];
}

Vector3D BezierPatch::evaluate(double u, double v) const
{
  std::vector<Vector3D> P_i;
  for (int i = 0; i < controlPoints.size(); i++) {
    P_i.push_back(evaluate1D(controlPoints[i], u));
  }
  return evaluate1D(P_i, v);
}

Section II: Triangle Meshes and Half-Edge Data Structure

Part 3: Area-weighted vertex normals

For smooth shading, we need to implement vertex normals. We accomplished that here by area-weight averaging the normals of each face adjacent to our vertex. In practice, that was achieved by adding the cross products of two half-edges from each face then normalizing. The code for that is demonstrated below. 

Vector3D n(0, 0, 0);
HalfedgeCIter h = halfedge();
do
{
  if (!h->face()->isBoundary())
  {
    Vector3D v1 = h->next()->vertex()->position - h->vertex()->position;
    Vector3D v2 = h->next()->next()->vertex()->position - h->next()->vertex()->position;
    n += cross(v1, v2);
  }
  h = h->twin()->next();
}
while (h != _halfedge);
return n.unit();

Phong shading looks much smoother than the flat shading alternative.

Part 4: Edge flip

Flipping an edge shared by triangles \((a, b, c)\) and \((b, a, d)\) replaces it with an edge connecting \(c\) and \(d\). The result is the two triangles \((c, d, b)\) and \((d, c, a)\). No elements are created or deleted. Only pointers change.

I implemented this in code by, essentially, 1. storing a pointer to each relevant edge, half-edge, face, and vertex and 2. assigning values accordingly. While it is a bit of a brute-force implementation, we need to check assignments are reasonable for every relevant object, which is easiest to achieve in this manner. Here, h_{i} represent half-edges, a-d are vertices, e_{i} are edges, and f_{i} are faces.

Part 5: Edge split

Splitting edge \((b, c)\), which is shared by triangles \((b, c, a)\) and \((c, b, d)\), inserts a new vertex \(m\) at the edge's midpoint and connects it to \(a\) and \(d\). The result is four triangles. This operation does create new elements:

  • 1 new vertex \(m\), at position \((b + c)/2\)
  • 3 new edges: \(m\)–\(a\), \(m\)–\(d\), and the second half of the original edge, \(m\)–\(c\)
  • 6 new half-edges (two per new edge)
  • 2 new faces

Part 6: Loop subdivision for mesh upsampling

Loop subdivision splits every triangle into four smaller ones and repositions vertices with weighted averages, which makes the mesh smoother. I implemented it in five passes:

  1. Compute new positions for old vertices. For each existing vertex with degree \(n\) and neighbor sum \(S\): \[ \text{newPosition} = (1 - n u)\,\text{position} + u\,S, \quad u = \begin{cases} 3/16 & n = 3 \\ 3/(8n) & \text{otherwise.} \end{cases} \] I also mark every existing vertex as isNew = false.
  2. Compute positions for the edge midpoints. For each edge \((A, B)\) with opposite vertices \(C\) and \(D\), I store \(\frac{3}{8}(A+B) + \frac{1}{8}(C+D)\) in e->newPosition. These positions have to be computed now, while the mesh is still the original one.
  3. Split every original edge. I split only edges whose endpoints are both old vertices, then copy the precomputed edge position into the new vertex's newPosition. New edges are appended to the edge list during iteration, so I save the next iterator before each split. The "both endpoints old" check makes sure the newly created edges are never split again.
  4. Flip new edges that connect an old vertex to a new vertex. This turns the split pattern into the standard 1-to-4 triangle subdivision.
  5. Commit positions. Copy newPosition into position for every vertex.
double u = (degree == 3) ? 3.0 / 16.0 : 3.0 / (8.0 * degree);
v->newPosition = (1.0 - degree * u) * v->position + u * neighborSum;

e->newPosition = 3.0 / 8.0 * (A + B) + 1.0 / 8.0 * (C + D);
